# 3주차 정렬 정리

| 정렬 | 파일 | 시간복잡도 | 핵심 아이디어 |
|---|---|---|---|
| 버블 정렬 | `03_01_bubble_sort.py` | O(N²) | 옆자리끼리 비교해서 큰 값을 뒤로 밀어낸다 |
| 선택 정렬 | `03_02_selection_sort.py` | O(N²) | 남은 구간에서 최솟값을 찾아 맨 앞과 교환 |
| 삽입 정렬 | `03_03_insertion_sort.py` | O(N²) (정렬된 경우 O(N)) | 앞쪽 정렬된 부분에 하나씩 끼워 넣는다 |
| 병합 | `03_04_merge.py` | O(N+M) | 정렬된 두 배열을 포인터 두 개로 합친다 |
| 병합 정렬 | `03_05_merge_sort.py` | O(N log N) | 반으로 쪼개고(분할) 정렬하며 합친다(정복) |

## 1. 버블 정렬 (Bubble Sort)

```python
for i in range(len(array) - 1, -1, -1):
    for j in range(i):
        if array[j] > array[j+1]:
            array[j], array[j+1] = array[j+1], array[j]
```

### 어떻게 정렬되나
1. 배열의 **맨 앞부터 끝까지 옆자리(`j`, `j+1`)끼리 비교**한다.
2. 왼쪽이 더 크면 자리를 바꾼다 → 큰 값이 계속 오른쪽으로 밀려간다.
3. 한 바퀴가 끝나면 그 구간의 **가장 큰 값이 맨 뒤에 확정**된다.
4. 확정된 뒷부분은 빼고(`i`를 1 줄이고) 다시 1번부터 반복.

### `[4, 6, 2, 9, 1]` 추적

| 바퀴 | 비교 과정 | 결과 |
|---|---|---|
| i=4 | `4>6`X, `6>2`✓, `6>9`X, `9>1`✓ | `[4, 2, 6, 1, \|9]` |
| i=3 | `4>2`✓, `4>6`X, `6>1`✓ | `[2, 4, 1, \|6, 9]` |
| i=2 | `2>4`X, `4>1`✓ | `[2, 1, \|4, 6, 9]` |
| i=1 | `2>1`✓ | `[1, \|2, 4, 6, 9]` |

`|` 오른쪽이 정렬 확정 구간. 뒤에서부터 한 칸씩 채워진다.

- 비교 횟수: `(N-1) + (N-2) + ... + 1` → **O(N²)**

## 2. 선택 정렬 (Selection Sort)

```python
for i in range(len(array) - 1):
    min_index = i
    for j in range(i, len(array)):
        if array[j] < array[min_index]:
            min_index = j
    array[i], array[min_index] = array[min_index], array[i]
```

### 어떻게 정렬되나
1. `i`번째 자리를 채울 차례라고 생각한다.
2. **아직 정렬 안 된 구간 `array[i:]` 전체를 훑어 최솟값의 위치**(`min_index`)를 찾는다.
3. 찾은 최솟값을 `i`번째 자리와 **딱 한 번 교환**한다.
4. `i`를 1 늘려 반복. 앞에서부터 한 칸씩 확정된다.

### `[4, 6, 2, 9, 1]` 추적

| i | 탐색 구간 | 찾은 최솟값 | 교환 후 |
|---|---|---|---|
| 0 | `[4, 6, 2, 9, 1]` | `1` (idx 4) | `[1, \|6, 2, 9, 4]` |
| 1 | `[6, 2, 9, 4]` | `2` (idx 2) | `[1, 2, \|6, 9, 4]` |
| 2 | `[6, 9, 4]` | `4` (idx 4) | `[1, 2, 4, \|9, 6]` |
| 3 | `[9, 6]` | `6` (idx 4) | `[1, 2, 4, 6, \|9]` |

`|` 왼쪽이 확정 구간. 버블과 반대로 **앞에서부터** 채워진다.

- 교환은 한 바퀴에 딱 한 번이라 swap 횟수는 적지만, 비교는 여전히 **O(N²)**.

## 3. 삽입 정렬 (Insertion Sort)

```python
for i in range(len(array) - 1):
    check_index = i + 1
    for j in range(i, -1, -1):
        if array[j] > array[check_index]:
            array[j], array[check_index] = array[check_index], array[j]
            check_index = j
        else:
            break   # 여기가 핵심
```

### 어떻게 정렬되나
1. `array[0..i]`는 **이미 정렬돼 있다고 가정**한다. (처음엔 원소 1개라 당연히 정렬 상태)
2. 그 다음 원소(`check_index = i+1`)를 손에 든다.
3. 정렬된 부분을 **뒤에서 앞으로** 훑으며, 나보다 큰 값은 한 칸씩 밀고 나는 그 자리로 이동.
4. 나보다 작거나 같은 값을 만나면 **제자리를 찾은 것이므로 `break`**.
5. 정렬된 구간이 한 칸 늘어난 상태로 2번 반복.

### `[4, 6, 2, 9, 1]` 추적

| i | 손에 든 값 | 과정 | 결과 |
|---|---|---|---|
| 0 | `6` | `4>6`X → 바로 break | `[4, 6, \|2, 9, 1]` |
| 1 | `2` | `6>2`✓ 밀기, `4>2`✓ 밀기 | `[2, 4, 6, \|9, 1]` |
| 2 | `9` | `6>9`X → 바로 break | `[2, 4, 6, 9, \|1]` |
| 3 | `1` | `9>1`✓, `6>1`✓, `4>1`✓, `2>1`✓ 계속 밀기 | `[1, 2, 4, 6, 9]` |

- 제자리를 찾으면 `break`로 바로 끝내기 때문에, **거의 정렬된 배열에서는 O(N)** 으로 빠르다.
  (위 표에서 `6`과 `9`는 비교 1번 만에 끝났다.)
- 3개 O(N²) 정렬 중 실전에서 가장 쓸만한 이유.

## 4. 병합 (Merge)

```python
while a < len(arr1) and b < len(arr2):
    if arr1[a] <= arr2[b]:
        result.append(arr1[a]); a += 1
    else:
        result.append(arr2[b]); b += 1
# 남은 쪽을 통째로 이어붙이기
```

### 어떻게 정렬되나
> 전제: **두 배열이 각각 이미 정렬돼 있어야 한다.**

1. 두 배열 맨 앞에 포인터 `a`, `b`를 놓는다.
2. `arr1[a]`와 `arr2[b]` 중 **작은 쪽을 결과에 담고, 담은 쪽 포인터만 한 칸 전진**.
3. 한쪽 포인터가 끝에 닿으면 반복 종료.
4. **남은 쪽 배열은 이미 정렬돼 있으니 통째로 뒤에 붙인다.**

### `[1, 2, 3, 5]` + `[4, 6, 7, 8]` 추적

| 비교 | 담는 값 | result |
|---|---|---|
| `1` vs `4` | `1` | `[1]` |
| `2` vs `4` | `2` | `[1, 2]` |
| `3` vs `4` | `3` | `[1, 2, 3]` |
| `5` vs `4` | `4` | `[1, 2, 3, 4]` |
| `5` vs `6` | `5` | `[1, 2, 3, 4, 5]` |
| arr1 소진 | 남은 `[6,7,8]` 붙이기 | `[1, 2, 3, 4, 5, 6, 7, 8]` |

- 각 원소를 딱 한 번씩만 보므로 **O(N+M)**.

## 5. 병합 정렬 (Merge Sort)

```python
def merge_sort(array):
    if len(array) <= 1:
        return array
    mid = len(array) // 2
    left = merge_sort(array[:mid])
    right = merge_sort(array[mid:])
    return merge(left, right)
```

### 어떻게 정렬되나
1. **분할**: 배열을 반으로 쪼갠다. 원소가 1개가 될 때까지 재귀적으로 계속 쪼갠다.
2. 원소 1개짜리는 **그 자체로 정렬된 상태** → 재귀 종료.
3. **정복**: 돌아오면서 정렬된 두 조각을 `merge`로 합친다.
4. 합쳐진 결과는 항상 정렬 상태이므로, 위 단계에서 또 `merge` 할 수 있다.

> ⚠️ `merge`는 원본을 고치지 않고 **새 리스트를 반환**한다.
> 그래서 `merge(left, right)`만 호출하고 버리면 안 되고, 반드시 `return` 해야 한다.

### `[5, 3, 2, 1, 6, 8, 7, 4]` 추적

```
분할 ↓
[5, 3, 2, 1, 6, 8, 7, 4]
[5, 3, 2, 1]      [6, 8, 7, 4]
[5, 3]  [2, 1]    [6, 8]  [7, 4]
[5][3]  [2][1]    [6][8]  [7][4]   ← 원소 1개, 정렬 완료

합치기 ↑ (merge)
[3, 5]  [1, 2]    [6, 8]  [4, 7]
[1, 2, 3, 5]      [4, 6, 7, 8]
[1, 2, 3, 4, 5, 6, 7, 8]
```

- 쪼개는 깊이가 `log N` 단계, 각 단계마다 전체 N개를 훑는 `merge` → **O(N log N)**.
- 단점: `merge` 결과를 담을 새 배열이 필요해 **공간복잡도 O(N)**.

## 정리 한 줄

- O(N²) 3형제는 **어떤 값을 언제 확정하느냐**의 차이
  - 버블: 뒤에서부터 최댓값 확정
  - 선택: 앞에서부터 최솟값 확정
  - 삽입: 앞쪽 정렬 구간에 끼워넣기
- 병합 정렬은 `merge`를 알고 나면 그냥 **"쪼개서 merge"** 가 전부.
